lfs-rl · seeking compute sponsorship

Debugging tasks where the damage is done early and the symptom appears much later, built from mistakes Claude Fable 5 actually made.

We ran Fable 5 as the operator of a real Linux system for months and recorded where it went wrong. It rarely failed at fixing a problem it had been handed. It failed at noticing something was wrong at all, hours after the actual mistake, with the evidence pointing somewhere else. Those recorded mistakes are what the tasks are made of.

A fault is planted in one software package, the build continues normally, and the breakage surfaces up to fourteen packages later. The agent is told nothing about where to look. Grading is not a judgement call, because a program is compiled and run inside the repaired system, and it either produces the right output or it does not.

Nobody knows how models perform on these. That is the point. The tasks are built and proven solvable, but they have never been run at scale. Long-horizon debugging is a known weak spot, and this measures it directly.

Spent so far

How it is built

The environment follows three published designs. RLVE keeps task difficulty matched to the model being trained, which is applied now and is why distance is a parameter. BPO forks rollouts from sandbox snapshots, which is why the substrate can fork at any package instead of rebuilding from scratch. TRACE assigns credit to individual steps of a long task, which is designed against our state-based grading and waits on training starting.

The ask

GPU compute to find out. A first meaningful run is about $300, a full programme a few thousand.

The environment, the fault generator and the grading already work. What is missing is the compute to run models against them.
