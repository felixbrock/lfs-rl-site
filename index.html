lfs-rl · seeking compute sponsorship

Debugging tasks where the damage is done early and the symptom appears much later, built from mistakes a frontier model actually made.

We ran a frontier model as the operator of a real Linux system for months and recorded where it went wrong. It rarely failed at fixing a problem it had been handed. It failed at noticing something was wrong at all, hours after the actual mistake, with the evidence pointing somewhere else.

Those recorded failures are now tasks. A fault is planted in one software package, the build continues normally, and the breakage surfaces up to fourteen packages later. The agent is told nothing about where to look. Grading is not a judgement call: a program is compiled and run inside the repaired system, and it either produces the right output or it does not.

Nobody knows how models perform on these. That is the point. The tasks are built and proven solvable, but they have never been run at scale against a model, and the one frontier attempt we could afford needed genuine detective work rather than a known fix. Long-horizon debugging is a known weak spot, and this measures it directly.

The ask

GPU compute to find out. A first meaningful run is about $300, a full programme a few thousand.

The environment, the fault generator and the grading are already built and working, on one laptop, for under $20 of GPU time.
